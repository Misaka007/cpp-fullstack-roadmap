# C++11 新特性

## 核心特性

| 分类 | 特性 | 解决的问题 |
| --- | --- | --- |
| 资源管理 | `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr` | 用类型表达所有权，降低泄漏风险 |
| 性能 | 右值引用、移动语义、`std::move` | 避免临时对象和容器扩容中的不必要拷贝 |
| 泛型 | `auto`、`decltype`、范围 `for` | 降低模板代码的类型书写负担 |
| 并发 | `std::thread`、互斥量、条件变量、原子类型 | 提供标准线程与同步抽象 |
| 接口 | Lambda、`std::function`、`override`、`final` | 提高可调用对象和多态接口的表达力 |
| 初始化 | 统一初始化、委托构造、`nullptr` | 减少初始化和空指针歧义 |

## 移动语义与完美转发

```cpp
template <class T>
void relay(T&& value) {
    consume(std::forward<T>(value));  // 保留实参原有的值类别
}
```

- `std::move` 只做类型转换，将表达式转为右值引用；它不执行移动操作。
- 命名的右值引用变量本身是左值；转发时必须使用 `std::forward<T>`。
- 移动后的对象必须保持有效且可析构，但其具体值通常不应再依赖。
- 移动构造函数若标记 `noexcept`，标准容器扩容时更可能选择移动而非拷贝。

## 并发基础

```text
共享数据 -> mutex 保护临界区
条件变化 -> condition_variable 通知等待者
无锁计数 -> atomic（仍需明确内存序）
```

- `std::thread` 在析构前必须 `join()` 或 `detach()`；否则程序会调用 `std::terminate`。
- 条件变量等待应使用谓词，处理伪唤醒：`cv.wait(lock, [] { return ready; });`。
- 原子变量只保证该变量的原子读写，不会自动使多个变量组成的业务状态保持一致。

## 编译与兼容性

```bash
g++ -std=c++11 -Wall -Wextra -Werror source.cpp -pthread
```

- `-pthread` 同时影响编译和链接；仅链接 `-lpthread` 可能遗漏编译期宏设置。
- 对外库接口要明确最低语言标准，避免头文件泄露高版本特性。

## 特性补充清单

### 语言特性

| 特性 | 用途 | 注意事项 |
| --- | --- | --- |
| 统一初始化 `{}` | 统一对象和容器初始化 | 会禁止窄化转换，也可能优先匹配 `initializer_list` 构造函数 |
| `nullptr` | 类型安全空指针 | 不使用 `0` 或 `NULL` 代替，避免重载歧义 |
| `constexpr` | 编译期可求值函数/对象 | C++11 的函数体限制较多，运行时调用同样合法 |
| 原始字符串 `R"(...)"` | 正则、路径、嵌入文本 | 自定义分隔符不得与内容冲突 |
| 用户定义字面量 | 为领域类型提供字面量 | 运算符命名受语言规则限制，避免制造歧义 |
| 属性 | 向编译器提供元信息 | 仅依赖标准属性，如 `[[noreturn]]`、`[[carries_dependency]]` |
| 变参模板 | 类型安全参数包 | 用递归、展开或索引序列处理参数包 |
| 模板别名 | 固化模板部分参数 | 使用 `using`，不使用无法模板化的 `typedef` |
| `static_assert` | 编译期断言 | 错误信息应说明违反的接口约束 |
| `enum class` | 强类型、带作用域枚举 | 需要显式转换到底层整数类型 |
| 默认成员初始化器 | 统一成员默认值 | 构造函数初始化列表可覆盖默认值 |
| `override` / `final` | 约束虚函数层次 | `override` 应作为所有覆写函数的默认标记 |

### 标准库补充

| 特性 | 典型用途 |
| --- | --- |
| `std::tuple` | 临时复合返回值；长期 API 更推荐具名结构体 |
| Type traits | 编译期类型分支、约束与元编程 |
| `<regex>` | 正则匹配；性能敏感路径需实测实现质量 |
| `<random>` | 引擎与分布分离的随机数生成 |
| `<chrono>` | `duration`、`time_point` 与单调时钟 |
| `unordered_map/set` | 平均 O(1) 哈希查找 |
| `forward_list` / `array` | 单链表和固定容量数组 |
| `emplace` | 容器内构造；不保证一定比 `push_back` 更快 |
| `exception_ptr` | 在线程/异步边界传递异常 |

## 逐项详解

### 语言特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| 内存模型 | 定义线程间可见性、数据竞争和 happens-before 规则，是原子操作与锁可移植的基础。 | `std::atomic<int> count{0};` | 没有同步的并发读写是数据竞争，行为未定义；原子并不自动保护复合不变量。 |
| `auto` | 由初始化表达式推导变量类型，减少冗长迭代器和模板类型。 | `auto it = map.find(key);` | 会丢失顶层 `const` 和引用；修改原对象时写 `auto&` 或 `const auto&`。 |
| `decltype` | 获取表达式的声明类型，适合泛型返回类型和精确保留引用。 | `decltype(obj.member) x;` | 对未加括号的实体名和一般表达式规则不同；不确定时用 `decltype((expr))` 验证。 |
| 范围 `for` | 基于 `begin/end` 展开遍历，简化容器循环。 | `for (const auto& x : values) {}` | `auto x` 会复制元素；遍历时修改容器可能使迭代器失效。 |
| 右值引用与移动 | `T&&` 区分可被“窃取资源”的临时值，使容器和返回值减少深拷贝。 | `buffer = std::move(other.buffer);` | `std::move` 只是转换；移动后对象仍有效但内容不可依赖。 |
| 统一初始化 | 用 `{}` 覆盖多数初始化形式，并禁止窄化。 | `std::vector<int> v{1, 2, 3};` | 会优先匹配 `initializer_list` 构造函数，`T{n}` 与 `T(n)` 含义可能不同。 |
| `nullptr` | 类型为 `std::nullptr_t` 的空指针字面量，解决 `0` 参与整数重载的问题。 | `open(nullptr);` | 只表达空指针，不能当整数使用。 |
| `constexpr` | 声明可参与常量求值的函数或对象，编译器可在条件满足时提前计算。 | `constexpr int square(int x) { return x * x; }` | C++11 函数体限制严格；调用是否常量求值取决于实参和上下文。 |
| 原始字符串 | `R"(...)"` 不处理反斜杠转义，适合正则、JSON 片段和 Windows 路径。 | `R"(C:\\tmp\\a.txt)"` | 内容含 `)"` 时需自定义分隔符，如 `R"tag(... )tag"`。 |
| 用户定义字面量 | 通过后缀把字面量直接转为领域类型。 | `auto t = 250ms;` | 只为清晰、无歧义的单位或值对象设计，不要滥用为隐式业务逻辑。 |
| 属性 | 用 `[[...]]` 给编译器和工具附加语义。 | `[[noreturn]] void fail();` | 优先使用标准属性；厂商属性应封装在兼容宏中。 |
| Lambda | 编译器生成带捕获成员和 `operator()` 的闭包对象。 | `[factor](int x) { return x * factor; }` | 异步回调按引用捕获外部局部变量会悬空；捕获 `this` 也不延长对象生命周期。 |
| 变参模板 | 参数包在编译期接收任意数量、任意类型参数。 | `template<class... Ts> void log(Ts&&... xs);` | 处理参数包必须使用展开、递归或索引序列；注意转发每个参数。 |
| 模板别名 | `using` 可以将模板部分实参固定为新模板名。 | `template<class T> using Vec = std::vector<T>;` | `typedef` 不能声明别名模板；别名不会创建新类型。 |
| `noexcept` | 说明函数不抛异常，并参与部分类型与容器优化决策。 | `Widget(Widget&&) noexcept;` | 若实际抛出会调用 `terminate`；只在确实能保证时标记。 |
| `override` / `final` | 编译期校验覆写关系，或禁止继续覆写/继承。 | `void run() override;` | 将所有预期覆写的虚函数标为 `override`，可避免签名细微不匹配。 |
| `static_assert` | 在编译期检查假设，失败时给出诊断。 | `static_assert(sizeof(void*) == 8, "64-bit required");` | 用于类型约束、平台约束，不用于运行时输入校验。 |
| `long long` | 至少 64 位的标准整数类型，配套无符号类型。 | `long long total = 0;` | 跨协议应优先使用 `<cstdint>` 的固定宽度类型。 |
| 默认成员初始化器 | 在成员声明处定义默认值，所有构造函数共享。 | `int retries = 3;` | 构造函数初始化列表给同一成员赋值时会覆盖默认值。 |
| `enum class` | 枚举项带作用域且不隐式转换为整数。 | `enum class State { idle, running };` | 与 C API 或位运算交互时需要显式转换和专门的运算符。 |

### 标准库特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| 智能指针 | `unique_ptr` 表示唯一所有权，`shared_ptr` 用控制块共享所有权，`weak_ptr` 观察共享对象。 | `auto p = std::make_unique<T>();` | 默认选 `unique_ptr`；`shared_ptr` 循环引用必须用 `weak_ptr` 断开。 |
| 原子与线程库 | `thread` 执行并发任务，mutex/CV 协调共享状态，future/promise 传递结果。 | `std::thread t(work); t.join();` | 线程必须 `join/detach`；条件变量必须配合谓词和同一把锁。 |
| `tuple` | 匿名异构值集合，可按索引或类型读取。 | `std::get<0>(tuple)` | 长期业务返回值用具名结构体更可读；结构化绑定是 C++17。 |
| Type traits | 用模板常量查询、转换类型属性。 | `std::is_integral<T>::value` | traits 只描述静态类型，不能替代对象运行时状态检查。 |
| 正则 | 以 ECMAScript 等语法做文本匹配、替换。 | `std::regex_match(s, re);` | 编译正则可能昂贵，性能敏感路径缓存对象并实测。 |
| 随机数 | 将随机引擎与概率分布分离。 | `std::mt19937 gen(seed);` | 不用 `rand()`；生产场景需选择可预测性与熵源合适的种子。 |
| 时间库 | `duration` 表示时长，`time_point` 表示时刻。 | `auto start = std::chrono::steady_clock::now();` | 测耗时用单调的 `steady_clock`，不要用可能校时跳变的系统时钟。 |
| `unordered_*` | 哈希表提供平均常数时间查找。 | `std::unordered_map<Key, Value> m;` | 最坏复杂度仍可能退化；自定义 key 要保持 hash 与相等关系一致。 |
| `forward_list` / `array` | 单链表节省链接开销；`array` 是固定大小的容器封装。 | `std::array<int, 4> a{};` | `forward_list` 无随机访问和 `size()`；`array` 大小是类型的一部分。 |
| `emplace` | 直接在容器存储位置构造元素。 | `users.emplace_back(name, id);` | 不要为“可能更快”而盲用；传同类型对象时 `push_back` 通常更直观。 |
| `exception_ptr` | 捕获异常对象后可跨线程保存并重新抛出。 | `auto e = std::current_exception();` | 只传递异常，不会自动同步线程；结果交接仍需 future 或其他同步机制。 |

### 横向对比

| 对比项 | `unique_ptr` | `shared_ptr` | 裸指针 |
| --- | --- | --- | --- |
| 所有权 | 唯一 | 共享 | 不表达所有权 |
| 开销 | 通常零额外开销 | 控制块和原子计数 | 无管理开销 |
| 适用场景 | 默认资源所有者 | 确有共享生命周期 | 非拥有观察或兼容接口 |

### 缺失知识点与工程注意事项

- Lambda 默认按值捕获会复制对象；异步任务按引用捕获必须保证被引用对象存活。
- 不要把 `std::move(const T&)` 当作优化：通常会得到 `const T&&`，无法调用常规移动构造。
- `weak_ptr::lock()` 是获得临时共享所有权的正确方式，避免检查后对象已销毁的竞态。

### 代码注释提示

```cpp
// 所有权：unique_ptr 表示唯一资源拥有者，调用方只能通过 move 转移。
// 转发：T&& 是转发引用；forward 保留实参的左值/右值类别。
// 并发：谓词与共享状态由同一把锁保护，避免伪唤醒和丢失通知。
```

### 可能的面试题

- **问题：** “解释 `std::move`、右值引用和完美转发之间的关系。”
- **简要答案：** `std::move` 将表达式转换为右值引用；移动是否发生由目标构造/赋值函数决定。转发引用经模板推导后使用 `std::forward<T>` 保留原始值类别，从而避免无谓拷贝。
