# C++23 新特性

## 核心特性

| 分类 | 特性 | 解决的问题 | 工程边界 |
| --- | --- | --- | --- |
| 对象模型 | 显式对象形参（deducing this） | 统一成员函数的 `const`、引用限定与 CRTP 写法 | 编译器和标准库支持仍应实测 |
| 编译期 | `if consteval`、`auto(x)` | 按求值阶段分支，显式获得衰退后的值副本 | 不要把编译期分支当作运行时特性开关 |
| 运算符 | 多维下标、静态 `operator()` / `operator[]` | 让多维视图和无状态可调用对象更自然 | 运算符语义必须直观、无隐藏昂贵操作 |
| 词汇类型 | `expected`、`mdspan`、`generator` | 表达可恢复错误、多维非拥有视图和惰性序列 | 明确所有权、错误策略与协程生命周期 |
| 容器与范围 | `flat_*` 容器、范围算法/视图增强 | 为读多写少的小型有序数据提供连续存储选择 | 插入、删除会移动元素，迭代器可能失效 |
| 诊断与工具 | `stacktrace`、`std::unreachable`、`to_underlying` | 改善故障定位和底层类型转换 | 栈踪迹的符号化依赖平台与构建选项 |

## 语言特性

```cpp
struct Counter {
    int value = 0;

    // 显式对象形参：同一实现可接受左值、右值和 const 对象。
    template <class Self>
    auto&& get(this Self&& self) {
        return std::forward<Self>(self).value;
    }
};

consteval int checked_size(int n) {
    if (n <= 0) throw "size must be positive";
    return n;
}

constexpr int choose(int x) {
    if consteval {
        return x * 2;  // 常量求值路径。
    } else {
        return x + 1;  // 运行时路径。
    }
}
```

- 显式对象形参把隐式的 `this` 写入参数列表，可减少 `const&`、`&&` 成员函数重复；返回时仍应使用 `std::forward<Self>` 保留值类别。
- `if consteval` 根据当前调用是否处于常量求值选择分支；它不同于 `if constexpr`，后者根据模板条件选择分支。
- `auto(x)` 产生按值的衰退副本，适合明确隔离可变对象；它会复制，不能代替转发引用。
- 多维下标允许 `matrix[row, col]` 形式，适合矩阵和张量接口；访问检查、布局和异常语义应由类型明确约定。
- `[[assume(expr)]]` 是优化提示，`expr` 不成立时行为未定义；只能写入已由逻辑保证的条件，不能拿来替代校验。
- `#elifdef`、`#elifndef`、`#warning` 改善条件编译可读性；功能探测仍优先使用标准特性测试宏。

## 标准库重点

| 特性 | 典型用途 | 面试与工程注意事项 |
| --- | --- | --- |
| `std::expected<T, E>` | 可预期失败的返回值 | 与异常二选一或分层使用；调用方必须处理 `error()` 分支 |
| `std::generator<T>` | 惰性枚举、流式读取 | 由协程驱动，元素引用与协程帧生命周期有关 |
| `std::mdspan` | 矩阵、图像、张量视图 | 不拥有数据；layout 和 mapping 决定寻址方式 |
| `std::flat_map` / `flat_set` | 小规模、读多写少有序索引 | 连续存储缓存友好，频繁中间插入成本高 |
| `string::contains` | 可读的包含判断 | 替代易写错的 `find(...) != npos` 模板代码 |
| `optional::and_then` 等 | 串联可能为空的计算 | 回调应保持无副作用，避免把错误吞掉 |
| `std::stacktrace` | 诊断未预期失败 | 发布环境的符号文件与隐私路径需管理 |
| `std::move_only_function` | 保存不可复制可调用对象 | 有类型擦除开销，适合所有权明确的回调 |
| `std::spanstream` | 固定缓冲区流式 I/O | 缓冲区由调用方拥有，避免越界与悬空 |
| `std::byteswap` / `to_underlying` | 字节序、枚举底层值 | 网络协议前后都要明确端序和整数宽度 |

```cpp
std::expected<int, std::string> parse_port(std::string_view text) {
    int port{};
    auto [ptr, ec] = std::from_chars(text.data(), text.data() + text.size(), port);
    if (ec != std::errc{} || ptr != text.data() + text.size() || port <= 0 || port > 65535) {
        return std::unexpected("invalid port");
    }
    return port;
}

std::optional<int> half_positive(int x) {
    if (x <= 0) return std::nullopt;
    return x / 2;
}

auto result = half_positive(8).transform([](int x) { return x * 10; });
```

## 逐项详解

### 语言特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| 显式对象形参 | 把隐式 `this` 写成第一个参数，可用模板统一处理 `const`、左值和右值对象。 | `template<class Self> auto&& get(this Self&& self);` | 需要正确转发 `Self`；改变了成员函数类型和部分重载规则，迁移现有接口要审查。 |
| `if consteval` | 根据当前调用是否正在常量求值选择分支。 | `if consteval { return checked(x); } else { return x; }` | 它依据求值上下文，不是按模板类型选分支；后者应使用 `if constexpr`。 |
| 多维下标 | `operator[]` 可接收多个下标，直接表达矩阵/张量访问。 | `matrix[row, col]` | 应明确行主序、越界策略和返回引用/代理对象的语义。 |
| 静态 `operator()` / `operator[]` | 无状态类型可将调用或下标运算符声明为静态成员。 | `static int operator()(int x);` | 只适合确实不依赖对象状态的操作；普通函数往往更易读。 |
| `auto(x)` | 显式按值创建表达式的衰退副本，去掉引用和顶层 cv。 | `auto copy = auto(value);` | 会发生拷贝或移动；不用于保留引用，也不能替代 `std::forward`。 |
| Lambda 属性 | 属性可作用于 Lambda，向编译器或工具传递元信息。 | `[] [[nodiscard]] { return compute(); }` | 属性支持度与具体属性语义需在目标工具链验证。 |
| 扩展浮点类型 | 可选提供 `float16_t`、`float128_t` 等精确宽度浮点类型。 | `std::float32_t value;` | 是可选能力，硬件、ABI、格式化和数值库支持并不一致。 |
| `Z/z` 字面量后缀 | 产生有符号 `size_t` 对应类型的整数字面量。 | `auto n = 42z;` | 避免混合有符号/无符号前仍需检查范围；兼容旧标准应避免暴露到公共头。 |
| `#elifdef` / `#elifndef` | 使多分支宏条件更可读。 | `#elifdef HAVE_EPOLL` | 宏仅是编译期配置，不应隐藏可替代的运行时行为差异。 |
| `#warning` | 在编译期发出非致命提醒。 | `#warning "legacy path"` | CI 中会增加噪音；迁移完成后应移除，不要长期依赖。 |
| `[[assume]]` | 告诉优化器某条件必为真，以便删除检查或生成更优代码。 | `[[assume(ptr != nullptr)]];` | 条件不成立即未定义行为；先验证外部输入，再对内部不变量作假设。 |
| UTF-8 源文件 | 规定可移植源码文件编码为 UTF-8 的方向。 | `u8"中文"` | 编码一致不等于运行时显示一致；终端、文件系统和第三方协议仍需约定编码。 |

### 标准库特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| 范围折叠与算法扩展 | 为 ranges 补齐更多算法和适配器，减少 iterator pair 样板。 | `std::ranges::fold_left(r, 0, plus{});` | 累加初值影响结果类型；注意惰性 view 的生命周期与算法的借用范围要求。 |
| 格式化增强 | 扩展格式化范围、元组等对象的支持。 | `std::format("{}", value);` | 自定义 formatter 要保持格式语义稳定；不把不可信文本直接作为格式串。 |
| `flat_*` 容器 | 用排序连续存储实现关联容器，改善遍历与缓存局部性。 | `std::flat_map<Key, Value> m;` | 中间插入/删除会搬移元素；不适合频繁写入或需稳定引用的场景。 |
| `mdspan` | 多维、非拥有视图，存储、布局和访问映射可分离。 | `std::mdspan view{data, rows, cols};` | 底层数据由外部拥有；shape、stride、layout 的契约应写清楚。 |
| `generator` | 协程驱动的惰性序列，每次迭代恢复协程产生下一个元素。 | `std::generator<int> numbers();` | 迭代器、yield 的引用和协程帧有生命周期关系，不能脱离 generator 随意保存。 |
| `contains` | 直接判断字符串或关联容器是否含某元素。 | `if (map.contains(id)) {}` | 只回答存在性；如果随后还要值，用一次 `find` 避免重复查找。 |
| `optional` 单子操作 | `and_then`、`transform`、`or_else` 串联可能无值的步骤。 | `opt.transform(f).and_then(g);` | 链条过长会隐藏控制流；错误原因重要时改用 `expected`。 |
| `stacktrace` | 捕获调用栈用于诊断。 | `std::stacktrace::current();` | 符号解析依赖构建选项和平台；不要把内部路径直接暴露给用户。 |
| `expected` | 将“成功值或错误值”编码进返回类型。 | `std::expected<T, E>` | 调用方必须显式处理错误；错误类型应稳定且可操作，避免仅用字符串。 |
| `move_only_function` | 类型擦除可调用对象，但不要求可复制。 | `std::move_only_function<void()> f;` | 有间接调用和可能的分配成本；适合转移 `unique_ptr` 的任务闭包。 |
| `spanstream` | 在调用方给定的连续缓冲区上提供流接口。 | `std::ospanstream out(buffer);` | 不拥有缓冲区，容量不足与数据长度需显式处理。 |
| `byteswap` | 反转整数对象的字节顺序。 | `auto be = std::byteswap(le);` | 只交换字节；网络协议还需根据主机端序和字段宽度决定何时调用。 |
| `to_underlying` | 安全、简洁地取枚举底层值。 | `auto code = std::to_underlying(state);` | 不是枚举合法性校验；来自外部的底层值转回枚举前仍需验证。 |
| 异构 `erase` | 允许以可比较但不同类型的键删除关联容器元素。 | `set.erase(std::string_view{"id"});` | 需要透明比较器/哈希与相等关系；检查目标库是否实现该重载。 |

### 面试考点全景图

| 维度 | 回答要点 | 面试高频追问 |
| --- | --- | --- |
| 核心定义 | C++23 以补齐 C++20 生态为主，重点落在显式对象形参、词汇类型和范围库扩展。 | `expected` 为什么不是异常的完全替代品？ |
| 关键角色 | 显式对象参数、协程帧、`expected` 的值/错误、`mdspan` 的 data handle 和 mapping。 | `mdspan` 是否拥有数组？ |
| 优点 | 接口表达更直接，错误通道与惰性数据处理更清晰。 | `flat_map` 为什么可能比 `map` 快？ |
| 风险 | 实现支持不齐、非拥有视图悬空、协程和类型擦除的生命周期问题。 | `generator` 迭代时谁拥有状态？ |
| 应用场景 | 协议解析、科学计算视图、读多写少索引、无异常错误处理。 | 何时选择 `expected`？ |

### 横向对比

| 对比项 | `optional<T>` | `expected<T, E>` | 异常 |
| --- | --- | --- | --- |
| 表达内容 | 有值或无值 | 有值或带类型的错误 | 非局部失败路径 |
| 调用方处理 | 判断是否有值 | 分支处理值或错误 | 可在上层统一捕获 |
| 适用场景 | 缺值本身正常 | 可预期且需反馈原因的失败 | 构造失败、难以就地恢复的错误 |

| 对比项 | `flat_map` | `std::map` | `std::unordered_map` |
| --- | --- | --- | --- |
| 内部布局 | 排序连续元素 | 节点树 | 哈希桶与节点/元素 |
| 查找 | 对数复杂度，局部性好 | 对数复杂度 | 平均常数复杂度 |
| 插入删除 | 中间位置移动元素 | 稳定对数复杂度 | 平均常数但可能 rehash |
| 适用场景 | 小型、读多写少 | 需稳定迭代器与有序操作 | 大量按键查询 |

### 缺失知识点与工程注意事项

- C++23 名义上可通过 `-std=c++23` 启用，但每个特性仍依赖编译器前端、标准库和链接环境；上线前使用特性宏和 CI 验证。
- `expected` 的错误类型应携带可操作信息，避免仅返回字符串；跨模块 API 还要稳定错误码或错误域。
- `mdspan`、`span`、`string_view` 都是非拥有视图，不能保存指向临时对象或可能扩容容器的视图。
- `std::unreachable()` 不是断言：实际可达时会触发未定义行为；先完成输入校验。
- `std::byteswap` 只交换字节，不完成主机/网络字节序协议转换的全部工作。

### 代码注释提示

```cpp
// 错误通道：expected 让调用方显式处理可恢复失败，避免忽略错误值。
// 所有权：mdspan/generator 的数据或协程帧生命周期必须长于使用者。
// 性能取舍：flat_map 查询局部性好，但中间插入会整体移动元素。
// 优化前提：[[assume]] 的条件必须已被证明，错误假设会导致未定义行为。
```

### 可能的面试题

- **问题：** `std::expected` 与异常应如何选择？
- **简要答案：** 对输入校验、网络返回码等可预期且调用方需要就地处理的失败，可用 `expected` 显式返回错误；对构造失败或跨多层传播且难以在当前层恢复的异常，可用异常。项目应统一边界策略，避免同一接口同时混用两套机制。

- **问题：** 为什么 `mdspan` 不直接替代 `vector`？
- **简要答案：** `mdspan` 是描述既有连续或可映射数据的多维非拥有视图，不负责分配、释放或扩容；`vector` 是一维拥有容器。两者常组合使用：`vector` 管理存储，`mdspan` 提供多维访问。
