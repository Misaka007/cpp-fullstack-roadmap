# C++20 新特性

## 核心特性

| 分类 | 特性 | 解决的问题 |
| --- | --- | --- |
| 泛型约束 | Concepts / `requires` | 将模板要求变为可读、可诊断的约束 |
| 范围库 | Ranges / Views | 将算法、筛选和转换组合为惰性管道 |
| 异步 | Coroutines | 用顺序代码表达挂起与恢复流程 |
| 模块化 | Modules | 降低头文件重复解析与宏污染 |
| 并发 | `std::jthread`、stop token、latch/barrier | 改进线程生命周期和协作取消 |
| 语言增强 | 三路比较、指定初始化、`consteval` | 提升类型表达与编译期计算能力 |

## Concepts 与 ranges

```cpp
template <std::integral T>
T gcd(T lhs, T rhs) {
    while (rhs != 0) {
        T next = lhs % rhs;
        lhs = rhs;
        rhs = next;
    }
    return lhs;
}

auto even = values | std::views::filter([](int x) { return x % 2 == 0; });
```

- Concepts 将“模板实例化失败”提前为接口约束错误，错误信息更接近调用点。
- Views 通常惰性求值且不拥有元素；源范围销毁或迭代失效后，view 同样失效。
- 将 view 返回给调用方时要确认底层范围的所有权；必要时返回拥有容器或 `owning_view`。

## 协程与取消

```text
caller -> coroutine frame -> co_await awaiter
                |                |
             suspend <--------- ready?
                |
             resume -> co_return -> destroy frame
```

- 协程不是线程；`co_await` 只定义挂起协议，调度器和执行线程由 awaiter/运行时决定。
- 协程帧可能动态分配；必须定义取消、异常传播和最终销毁策略，避免悬空 `coroutine_handle`。
- `std::jthread` 析构时自动请求停止并 join；任务代码仍需主动检查 `stop_token` 才能及时退出。

## Modules 与兼容性

```cpp
export module math;
export int add(int lhs, int rhs) { return lhs + rhs; }
```

- Modules 不是简单替换 `#include`：构建系统需要管理模块接口编译产物和依赖顺序。
- 第三方库与工具链对 modules 的支持程度不一；在跨平台项目中应制定回退策略。

## 特性补充清单

| 特性 | 说明 | 工程注意事项 |
| --- | --- | --- |
| 指定初始化 | `.field = value` 初始化聚合体 | 顺序受声明顺序约束，不能像 C99 任意乱序 |
| `<=>` | 三路比较生成比较结果 | 自动生成规则受成员类型比较能力影响 |
| `[*this]` 捕获 | Lambda 按值复制当前对象 | 复制成本和对象可复制性需要评估 |
| `[[no_unique_address]]` | 允许空成员不占额外空间 | 布局是优化，不应用于 ABI 假设 |
| `[[likely]]` / `[[unlikely]]` | 分支概率提示 | 仅在测量证明热分支时使用 |
| 扩展 `constexpr` | 常量求值中允许更多语句 | 不是所有动态行为都能成为常量表达式 |
| `consteval` | 强制编译期求值 | 适合验证和生成常量，不适合运行时数据 |
| `constinit` | 保证静态初始化 | 不代表对象不可修改，也不代表 `constexpr` |
| `using enum` | 引入枚举成员名 | 注意作用域污染与命名冲突 |
| `std::format` | 类型安全格式化 | 目标标准库实现支持度需检查 |
| 日历/时区 | `chrono` 日历和时区数据库 | 时区数据部署和夏令时歧义需处理 |
| `std::span` | 连续内存的非拥有视图 | 必须保证底层数组或容器仍存活 |
| `source_location` | 低成本采集调用位置 | 用于日志/断言，不要暴露敏感路径 |
| `barrier` / `latch` | 多线程阶段同步 | `latch` 一次性，`barrier` 可复用 |
| 特性测试宏 | 按实现能力条件编译 | 优先检测具体 `__cpp_*` 宏，而非只检测编译器版本 |
| `bit_cast` 与位操作 | 安全按位重解释与位工具 | `bit_cast` 只用于等大小 trivially copyable 类型 |

## 逐项详解

### 语言特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| Modules | 用 `export module` 声明显式模块边界，减少重复解析和宏泄漏。 | `export module math;` | 构建系统须管理模块依赖与 BMI；不能假定所有三方库和工具都支持。 |
| Concepts | 用 `concept` / `requires` 描述模板实参必须满足的接口。 | `template<std::integral T> T add(T, T);` | 约束应表达语义而非偶然实现细节；不是运行时校验。 |
| Coroutines | `co_await`、`co_yield`、`co_return` 把函数转换为可挂起状态机。 | `task<int> fetch();` | 不是线程；协程帧所有权、恢复线程、取消和异常传播必须由库设计。 |
| 指定初始化 | 用成员名初始化聚合对象，提高字段可读性。 | `Config c{.port = 80, .tls = true};` | 必须按成员声明顺序，限制比 C99 更严格。 |
| `<=>` | 三路比较一次给出小于、相等或大于，并可生成其他比较运算符。 | `auto operator<=>(const T&) const = default;` | 成员比较能力决定生成结果；浮点的偏序与 NaN 需单独处理。 |
| `[*this]` 捕获 | Lambda 按值复制当前对象而非只复制指针。 | `[*this] { return state_; }` | 复制可能昂贵，也要求对象可复制；并不共享后续状态变化。 |
| `[[no_unique_address]]` | 允许空成员与其他成员重叠存储，减少包装器空间。 | `[[no_unique_address]] Alloc alloc_;` | 只作布局优化，不能写依赖成员地址或 ABI 布局的逻辑。 |
| `[[likely]]` / `[[unlikely]]` | 向优化器提示分支概率。 | `if (ok) [[likely]] {}` | 测量前不要使用；错误提示可能损害优化。 |
| 扩展 `constexpr` | 常量求值中允许更多语句、动态分配等能力。 | `constexpr auto table = make_table();` | 动态分配必须在常量求值中完成释放；不能把运行时资源带到常量对象。 |
| `consteval` | 立即函数必须在编译期求值。 | `consteval int id(char c) { return c - 'A'; }` | 运行时实参会导致编译错误，适用于编译期验证而非通用 API。 |
| `constinit` | 强制具有静态存储期的变量进行静态初始化。 | `constinit int counter = 0;` | 不等于常量，运行时仍可修改；主要解决静态初始化顺序问题的一部分。 |
| `using enum` | 将枚举成员引入当前作用域，少写限定名。 | `using enum Color;` | 可读性与命名冲突需权衡，公共头文件中慎用。 |

### 标准库特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| Ranges / views | range 是可迭代序列，view 通常是惰性、轻量、非拥有适配器。 | `v | std::views::filter(pred)` | view 可能悬空且谓词可能重复执行；返回前确认底层范围存活。 |
| `format` | 编译期检查格式字符串的类型安全格式化接口。 | `std::format("id={}", id)` | 目标标准库支持与区域设置行为需验证；格式字符串不可来自不可信输入。 |
| 日历与时区 | `chrono` 加入日期、时区和夏令时规则表达。 | `std::chrono::zoned_time z{zone, tp};` | 时区数据库部署、缺失和夏令时歧义都要处理。 |
| `span` | 对连续元素的非拥有、带长度视图。 | `void f(std::span<const int> xs);` | 不能返回指向局部数组的 span；扩容会使指向 vector 的 span 失效。 |
| `source_location` | 在调用点低成本采集文件、行号、函数名。 | `log(msg, std::source_location::current());` | 日志可能泄露构建路径，发布环境应脱敏或映射。 |
| `barrier` / `latch` | `latch` 是一次性计数等待，`barrier` 支持反复阶段同步。 | `latch.count_down(); latch.wait();` | 等待者数和异常退出路径必须设计，否则容易永久阻塞。 |
| 原子扩展 | 原子等待/通知等减少轮询，补足并发原语。 | `flag.wait(false); flag.notify_one();` | 仍需要正确的内存序与状态机，不要把 wait 当作条件变量的无脑替代。 |
| 特性测试宏 | 标准宏表示具体语言或库能力。 | `#if __cpp_lib_span >= 202002L` | 先包含相应头文件，且在 CI 中编译验证降级路径。 |
| `bit_cast` 与位操作 | `bit_cast` 复制对象表示，`popcount` 等提供标准位运算。 | `std::popcount(mask);` | `bit_cast` 要求同大小且 trivially copyable；对象表示不等于跨平台协议格式。 |

### 缺失知识点与工程注意事项

- `views::filter` 等 range adaptor 会多次调用谓词；谓词应避免改变外部状态。
- 协程接口需要明确谁拥有 `task`、何时销毁协程帧、异常如何传给调用者。
- `stop_token` 不是强制取消；阻塞 I/O、长计算和第三方调用必须显式设置中断点。

### 代码注释提示

```cpp
// 约束：requires 明确模板实参必须满足的操作集合。
// 生命周期：view 不拥有底层范围，返回前确认源对象仍然存活。
// 协程：挂起不等于新线程；恢复线程和取消策略由 awaiter 定义。
```

### 可能的面试题

- **问题：** “C++20 协程和线程的关系是什么？”
- **简要答案：** 协程是可挂起、恢复的控制流抽象，不自带线程或调度器；它可以在同一线程上运行，也可以由异步运行时在不同线程恢复。线程负责执行，协程负责组织异步逻辑。
