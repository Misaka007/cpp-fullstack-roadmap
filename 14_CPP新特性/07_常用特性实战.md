# C++ 常用现代特性实战

本章按日常开发的使用频率组织，优先掌握 C++11、C++14、C++17 和 C++20 中能直接改善安全性、可读性与性能的特性。

## 高频特性速查

| 优先级 | 特性 | 常用版本 | 解决的问题 | 首选实践 |
| --- | --- | --- | --- | --- |
| 必会 | RAII、`unique_ptr` | C++11 | 资源泄漏与异常路径清理 | 默认独占所有权，资源放进对象析构函数 |
| 必会 | 移动语义、`std::move`、`std::forward` | C++11 | 大对象不必要拷贝 | 仅在不再需要源对象时移动 |
| 必会 | Lambda、范围 `for`、`auto` | C++11 | 回调与遍历样板代码 | 捕获最小化，避免悬空引用 |
| 必会 | `enum class`、`constexpr`、`static_assert` | C++11 | 类型安全和编译期约束 | 用强枚举表达有限状态 |
| 高频 | `make_unique`、泛型 Lambda | C++14 | 异常安全构造与通用回调 | 用 `make_unique` 代替裸 `new` |
| 高频 | `optional`、`variant`、`string_view` | C++17 | 缺值、互斥类型和只读字符串参数 | 明确生命周期与错误语义 |
| 高频 | 结构化绑定、`filesystem`、`from_chars` | C++17 | 解包结果、路径和高性能解析 | 对外边界检查错误码 |
| 高频 | `span`、ranges、`jthread` | C++20 | 非拥有序列、组合式处理和线程收尾 | 视图不保存临时对象，线程支持停止 |

## 资源与所有权

```cpp
class FileHandle {
public:
    explicit FileHandle(std::FILE* file) : file_(file) {}
    ~FileHandle() {
        if (file_ != nullptr) std::fclose(file_);
    }

    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;
    FileHandle(FileHandle&&) = delete;  // 简化示例：句柄不允许转移。

private:
    std::FILE* file_ = nullptr;
};

auto connection = std::make_unique<Connection>(config);
// 所有权：connection 离开作用域时自动释放；不把 get() 的裸指针长期保存。
Connection* observer = connection.get();
```

- `unique_ptr` 表示唯一所有者；需要转移时写 `std::move(ptr)`，移动后原指针为空但仍有效。
- `shared_ptr` 只用于确实存在共享生命周期的对象图；循环引用用 `weak_ptr` 打破，否则对象不会释放。
- 原始指针和引用通常表达非拥有访问。接口中应通过命名、注释或类型清楚说明生命周期要求。
- 优先让容器直接存储对象；仅当多态、稳定地址或昂贵移动确有必要时再存储智能指针。

## 值类别、容器与算法

```cpp
struct User {
    std::string name;
    int score{};
};

std::vector<User> users;
users.emplace_back("alice", 95);  // 原地构造；不是所有场景都天然更快。

std::sort(users.begin(), users.end(), [](const User& lhs, const User& rhs) {
    return lhs.score > rhs.score;
});

auto found = std::find_if(users.begin(), users.end(), [](const User& user) {
    return user.name == "alice";
});
```

- `std::move` 本身不移动任何数据，只是把表达式转换为右值；实际移动由目标类型的移动构造或移动赋值完成。
- 对仍要继续使用的对象不要随意 `std::move`；移动后对象只保证“有效但状态未指定”。
- `emplace_back` 直接在容器内构造，适合构造参数已在手的情况；传入同类型临时对象时与 `push_back` 不一定有差异。
- 优先组合标准算法，而不是手写下标循环；比较器必须满足严格弱序，否则 `sort` 行为不可靠。
- 容器扩容、`erase` 和 `insert` 的迭代器失效规则不同；修改容器后不要假设旧迭代器仍可用。

## 常用词汇类型与边界解析

```cpp
std::optional<int> parse_id(std::string_view text) {
    int value{};
    auto [end, ec] = std::from_chars(text.data(), text.data() + text.size(), value);
    if (ec != std::errc{} || end != text.data() + text.size() || value < 0) {
        return std::nullopt;
    }
    return value;
}

void print_name(std::string_view name) {
    // 参数视图：调用期间读取即可；不能保存 name 指向的临时字符串。
    std::cout << name << '\n';
}

std::span<const int> first_three(std::span<const int> values) {
    return values.first(std::min<std::size_t>(3, values.size()));
}
```

| 类型 | 表达的语义 | 常见错误 |
| --- | --- | --- |
| `std::optional<T>` | 合法结果可能不存在 | 用 `value()` 前未判断，导致抛出异常 |
| `std::variant<A, B>` | 恰好属于多种类型之一 | 错误 `get<T>`；优先用 `visit` 或 `get_if` |
| `std::string_view` | 非拥有只读字符序列 | 保存指向临时 `std::string` 的 view |
| `std::span<T>` | 非拥有连续元素视图 | 返回指向局部数组或已扩容容器的 span |
| `std::filesystem::path` | 平台相关路径语义 | 用字符串拼接路径，忽略分隔符与编码 |

- `string_view` 和 `span` 适合函数参数，能避免复制；若对象需要跨调用保存数据，应复制为拥有类型。
- `from_chars` 不分配内存、不依赖区域设置，适合协议和配置解析；必须检查错误码及是否完整消费输入。
- `optional` 表示“没有值”即可，若调用方需要错误原因，使用 `expected<T, E>` 或项目统一的 `Result` 类型。

## 并发与 C++20 ranges

```cpp
std::jthread worker([](std::stop_token stop) {
    while (!stop.stop_requested()) {
        do_one_unit_of_work();
    }
});

auto names = users
    | std::views::filter([](const User& user) { return user.score >= 60; })
    | std::views::transform([](const User& user) { return user.name; });
```

- `jthread` 析构时请求停止并等待线程结束；任务函数必须周期性检查 `stop_token`，阻塞调用还需设计唤醒机制。
- `mutex` 保护共享状态时使用 `std::lock_guard` 或 `std::scoped_lock`，不要手工 `lock()`/`unlock()`。
- range view 通常惰性、不拥有数据；不要从函数返回依赖局部容器的 view。
- 若只是一次性处理，传统算法通常更直观；ranges 适合多步骤筛选、转换和组合。

### 横向对比

| 对比项 | `unique_ptr` | `shared_ptr` | 裸指针/引用 |
| --- | --- | --- | --- |
| 所有权 | 唯一拥有 | 引用计数共享拥有 | 通常仅观察 |
| 复制 | 禁止，允许移动 | 复制会增加引用计数 | 不表达生命周期 |
| 成本 | 接近裸指针 | 控制块与原子计数开销 | 最低，但易误用 |
| 适用场景 | 默认资源所有权 | 真正共享生命周期 | 临时、非拥有访问 |

| 对比项 | `std::string` | `std::string_view` | `const char*` |
| --- | --- | --- | --- |
| 所有权 | 拥有字符 | 非拥有 | 非拥有且依赖终止符 |
| 长度 | 自带长度 | 自带长度 | 通常需扫描或额外传入 |
| 适用场景 | 存储、跨边界持久化 | 只读参数、切片 | C API 互操作 |

### 缺失知识点与工程注意事项

- `shared_ptr` 的控制块引用计数通常是线程安全的，但被管理对象本身的读写并不自动线程安全。
- Lambda 默认按值捕获可避免悬空引用，但可能复制大对象或错误捕获 `this`；异步任务中应格外检查对象存活。
- `auto` 可能丢失引用和顶层 `const`，需要保留精确类型时使用 `auto&`、`const auto&` 或 `decltype(auto)`。
- 不要以“减少拷贝”为由到处传 `const T&`：小型可复制值、所有权转移和异步边界通常应按值传递。
- 启用 sanitizer、严格警告和线程检测，才能较早发现越界、悬空、未初始化与数据竞争。

### 可能的面试题

- **问题：** 为什么 `std::make_unique` 通常优于 `new` 后立即交给智能指针？
- **简要答案：** 它把分配和所有权接管合成一个表达式，减少异常路径中裸指针泄漏的窗口，代码也更简洁；数组和自定义删除器等场景仍需按接口需求处理。

- **问题：** `std::string_view` 能否替代所有 `const std::string&` 参数？
- **简要答案：** 不能。它适合调用期间的只读文本访问，但不拥有数据；若函数要保存参数、需要保证以 `\\0` 结尾、或接口语义要求 `std::string`，仍应使用拥有类型或显式复制。
