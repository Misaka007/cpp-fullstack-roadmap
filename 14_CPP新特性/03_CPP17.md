# C++17 新特性

## 核心特性

| 分类 | 特性 | 价值 |
| --- | --- | --- |
| 类型与绑定 | 结构化绑定、`if constexpr`、类模板参数推导 | 简化泛型和解构代码 |
| 值语义 | 保证部分场景的复制消除、`std::string_view` | 减少临时对象与字符串复制 |
| 和类型 | `std::optional`、`std::variant`、`std::any` | 更明确地表达可选值和多类型值 |
| 文件系统 | `std::filesystem` | 标准化路径和目录操作 |
| 并行 | 并行算法执行策略 | 为算法提供并行化接口 |

## 结构化绑定与 `string_view`

```cpp
auto [name, score] = get_record();

std::string_view prefix(std::string("temporary"));  // 错误：悬空视图
```

- 结构化绑定可能是副本，也可能是引用，取决于声明中的 `auto`、`auto&` 或 `const auto&`。
- `std::string_view` 不拥有字符；它适合传参和切片，不适合保存指向短生命周期字符串的数据。
- `string_view::data()` 不保证以 `\0` 结尾，不能直接传给只接受 C 字符串的 API。

## `optional`、`variant` 与错误表达

```cpp
std::optional<User> find_user(Id id);
std::variant<Value, ParseError> parse(std::string_view input);
```

| 类型 | 表达含义 | 访问方式 |
| --- | --- | --- |
| `optional<T>` | 有值或无值 | `if (x)`、`value_or` |
| `variant<Ts...>` | 多个互斥备选类型之一 | `std::visit`、`get_if` |
| `any` | 运行时任意类型 | `any_cast`，类型信息运行时检查 |

- `optional` 只说明“可能没有值”，不携带失败原因；需要错误详情时使用 `variant` 或项目定义的 `expected` 类型。
- `variant` 的访问必须处理所有备选类型；异常路径或 `valueless_by_exception` 也应纳入设计。

## `if constexpr` 与并行算法

```cpp
template <class T>
auto absolute(T value) {
    if constexpr (std::is_signed_v<T>) return value < 0 ? -value : value;
    else return value;
}
```

- `if constexpr` 会丢弃未选分支的实例化，适合按类型选择实现；普通 `if` 不会。
- 并行执行策略要求操作满足无数据竞争、无依赖顺序等约束；不要把有副作用的共享状态直接放进并行算法回调。

## 特性补充清单

| 特性 | 说明 | 面试易错点 |
| --- | --- | --- |
| 保证复制省略 | 特定 prvalue 初始化场景无需移动/拷贝构造 | 不等于所有 NRVO 都被强制保证 |
| 超对齐动态分配 | 支持超出 `max_align_t` 的对象分配 | 自定义分配器也必须满足对齐要求 |
| 求值顺序增强 | 部分表达式顺序更明确 | 不要因此假设所有子表达式从左到右求值 |
| UTF-8/十六进制浮点字面量 | 增强字面量表达 | 源文件编码与执行字符集仍需明确 |
| 折叠表达式 | 简化参数包归约 | 空参数包需选择有初值的形式 |
| `auto` 非类型模板参数 | 允许值模板参数类型推导 | 要关注链接期常量与可用类型限制 |
| CTAD | 从构造实参推导类模板参数 | 推导指南和 `initializer_list` 可能导致意外类型 |
| 初始化器 `if/switch` | 缩小临时变量作用域 | 初始化变量在整个选择语句中可见 |
| inline 变量 | 头文件中定义全局变量 | 仍应控制可变全局状态 |
| `[[nodiscard]]` | 强制关注返回值 | 适合错误码、资源句柄和计算结果 |
| `std::byte` | 表示原始字节 | 不能与字符/整数隐式混用 |
| `to_chars/from_chars` | 无区域设置、无分配的数值转换 | 调用方必须检查 `ptr` 与 `ec` |
| 多态分配器 | 运行时可替换内存资源 | 资源生命周期必须长于使用它的容器 |
| `scoped_lock` | 一次锁定多把互斥量 | 避免手写多锁顺序导致死锁 |

## 逐项详解

### 语言特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| 保证复制省略 | 特定 prvalue 直接构造目标对象，不要求类型存在移动/拷贝构造。 | `return Widget{};` | 命名返回值优化（NRVO）仍不是所有情形都强制；不要依赖构造/析构副作用。 |
| 超对齐动态分配 | `new` 可正确分配 `alignas(64)` 等超对齐对象。 | `struct alignas(64) CacheLine {};` | 自定义 allocator、内存池和 placement new 也要满足对齐要求。 |
| 求值顺序增强 | 若干表达式规定了更明确的先后关系，降低旧式未定义行为。 | `obj.method(arg1(), arg2());` | 不是“所有参数从左到右”；有副作用的表达式仍应拆成多句。 |
| UTF-8 与十六进制浮点字面量 | `u8"..."` 表达 UTF-8，`0x1.8p+1` 精确表达二进制浮点。 | `auto x = 0x1.8p+1;` | C++20 起 `u8` 字面量元素类型有变化；文本编码、终端和文件系统仍需统一约定。 |
| 折叠表达式 | 用一个运算符对参数包做归约，替代递归模板。 | `(args + ...)`、`(fn(args), ...)` | 空包只对部分运算符有定义；通用场景提供初值，如 `(0 + ... + args)`。 |
| `auto` 非类型模板参数 | 模板值参数的类型可自动推导。 | `template<auto N> struct Buffer {};` | 参数仍须是允许的常量模板实参；值进入类型，会影响实例数量和符号名。 |
| CTAD | 根据构造函数实参推导类模板参数。 | `std::pair p{1, "ok"};` | `initializer_list` 和推导指南可能得到意外类型；公开 API 中必要时显式写类型。 |
| 初始化器 `if/switch` | 把查找结果等临时变量限制在选择语句作用域。 | `if (auto it = m.find(k); it != m.end()) {}` | 初始化变量在 `else` 也可见，但离开整个语句即销毁。 |
| `constexpr` Lambda | Lambda 可在满足条件时常量求值。 | `constexpr auto sq = [](int x) { return x*x; };` | 捕获和调用路径仍须满足常量表达式规则。 |
| inline 变量 | 允许在多个翻译单元包含的头文件中定义同一变量。 | `inline constexpr int max_size = 1024;` | 解决 ODR 多重定义，不等于并发安全；可变全局状态仍应谨慎。 |
| 结构化绑定 | 将数组、pair、tuple 或聚合对象拆为多个名字。 | `auto& [key, value] = *it;` | `auto` 往往复制，`auto&` 才绑定原对象；绑定名不是普通可捕获变量的完全等价形式。 |
| 属性 | `[[nodiscard]]` 防漏用结果，`[[maybe_unused]]` 抑制有意未用警告，`[[fallthrough]]` 标记贯穿。 | `[[nodiscard]] Result open();` | `nodiscard` 用于忽略就危险的返回值，不能代替错误处理。 |
| 底层值初始化枚举 | 可从底层整数显式初始化枚举。 | `Color c{1};` | 数值不一定对应有效枚举项；外部输入仍要验证范围。 |

### 标准库特性

| 特性 | 机制与价值 | 典型写法 | 使用边界 |
| --- | --- | --- | --- |
| `filesystem` | 提供路径、目录遍历和文件操作的跨平台抽象。 | `std::filesystem::path p{"config.json"};` | 文件系统操作会失败或抛异常；批处理可用 `error_code` 重载。 |
| 并行算法 | 用执行策略表示可并行或向量化的算法调用。 | `std::sort(std::execution::par, begin, end);` | 回调必须无数据竞争、无顺序依赖；实现不保证一定并行或加速。 |
| 特殊数学函数 | 标准化部分统计和数值计算函数。 | `std::cyl_bessel_j(0, x);` | 关注数值范围、精度和目标标准库实现支持。 |
| `string_view` | 常量时间切片的非拥有字符串视图。 | `name.remove_prefix(3);` | 不保证 `\0` 终止，且绝不能持久引用临时字符串。 |
| `any` | 类型擦除容器，可在运行时保存任意可复制类型。 | `std::any value = 42;` | `any_cast` 可能失败；若备选集合固定，`variant` 更安全高效。 |
| `variant` | 类型安全的判别联合，任一时刻保存一个备选类型。 | `std::visit(visitor, value);` | 用 `visit` 穷尽处理；赋值抛异常时可能处于 `valueless_by_exception`。 |
| `optional` | 表示存在或不存在的值。 | `if (auto v = find(); v) use(*v);` | 无值不等于错误原因；不要用它表达三种以上状态。 |
| `invoke` | 统一调用普通函数、成员函数指针和函数对象。 | `std::invoke(f, args...);` | 模板工具中很有用；业务代码直接调用通常更清晰。 |
| `to_chars/from_chars` | 无分配、无区域设置的数值格式化与解析。 | `std::from_chars(first, last, value);` | 检查 `ec` 和结束指针；浮点支持度应在目标工具链验证。 |
| PMR | `memory_resource` 将容器分配策略与容器类型分离。 | `std::pmr::vector<int> v{&pool};` | 内存资源必须活得比容器久；单调资源释放是整体释放，不逐对象回收。 |
| `scoped_lock` | 一次获取一把或多把锁，内部采用避免死锁的锁定算法。 | `std::scoped_lock lock(a, b);` | 锁粒度和临界区仍要尽量小；不要在持锁时调用未知外部代码。 |

## 面试辅导

### 面试考点全景图

| 维度 | 回答要点 | 面试高频追问 |
| --- | --- | --- |
| 核心定义 | C++17 增强了值语义、类型表达、文件系统和泛型分支。 | `string_view` 为什么会悬空？ |
| 关键角色 | 结构化绑定、视图类型、`optional`、`variant`、`if constexpr`。 | `optional` 与异常如何选择？ |
| 优点 | 减少样板代码并显式表达状态。 | `variant` 如何保证穷尽处理？ |
| 风险 | 非拥有视图悬空、错误忽略、并行数据竞争。 | 并行算法何时不适合？ |
| 应用场景 | 解析、配置、路径操作和泛型库。 | 如何兼容旧标准库？ |

3. `optional` 为什么不能完整替代异常或错误码？
4. `variant` 和面向对象多态如何选择？
5. 并行算法如何避免竞态和性能退化？

### 横向对比

| 对比项 | `optional<T>` | `variant<T, E>` | 异常 |
| --- | --- | --- | --- |
| 失败信息 | 无 | 可携带错误类型 | 可携带异常对象 |
| 控制流 | 显式检查 | 显式分支 | 非局部跳转 |
| 适用场景 | 缺值是正常状态 | 预期的可恢复失败 | 非预期或跨层错误 |

### 缺失知识点与工程注意事项

- 视图类型都需要审查生命周期：`span`、`string_view`、迭代器和引用都不拥有底层数据。
- `std::filesystem` 操作可能抛出异常；批处理工具可使用带 `error_code` 的重载集中处理错误。
- 平行算法的实际并行度依赖实现与运行环境，不能仅因传入执行策略就假设一定加速。

### 代码注释提示

```cpp
// 所有权：string_view 仅借用字符，调用方必须保证底层字符串在使用期间存活。
// 状态：variant 用 visit 穷尽处理所有备选类型，避免遗漏错误分支。
// 并发：并行回调不得写入未同步的共享状态。
```

### 可能的面试题

- **问题：** “`std::string_view` 有何优势和风险？”
- **简要答案：** 它避免复制并支持 O(1) 切片，但不拥有数据；保存它或传给要求 C 字符串的接口前必须确认底层字符生命周期和终止符约束。
