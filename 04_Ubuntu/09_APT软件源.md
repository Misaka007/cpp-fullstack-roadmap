Ubuntu 使用 APT 管理软件包。软件源决定包索引和下载地址，修改源前应备份配置并确认发行版代号。

## 一、APT 软件源

Ubuntu 24.04+ 常使用 `/etc/apt/sources.list.d/ubuntu.sources`，旧版本常使用 `/etc/apt/sources.list`。

```text
Types: deb
URIs: https://archive.ubuntu.com/ubuntu
Suites: noble noble-updates noble-security
Components: main universe restricted multiverse
```

修改软件源后执行 `sudo apt update` 刷新索引；若出现签名错误，应检查发行版代号、网络代理和仓库签名，而不是关闭安全校验。

## 二、APT 常用命令

```bash
sudo apt update                 # 刷新软件包索引
apt search <keyword>            # 搜索软件包
apt show <package>              # 查看软件包信息
sudo apt install <package>      # 安装软件包
sudo apt remove <package>       # 卸载软件包，保留配置
sudo apt purge <package>        # 卸载软件包和配置
sudo apt autoremove             # 清理不再需要的依赖
apt list --upgradable           # 查看可更新软件包
```

生产环境升级前应先查看更新列表并在测试环境验证；不要直接执行不受控的全量升级。

### 面试官追问链

1. **基础：** 请定义 `APT软件源`，说明它的输入、输出和核心约束。
2. **机制：** 命令语义、文件/进程/权限模型、配置生效范围和错误诊断；关键状态如何变化？
3. **深入：** 与相近命令、配置方式或系统服务相比，生效时机、作用范围、权限要求、可移植性和回滚成本有什么不同？
4. **工程：** 失败、边界输入、资源耗尽或并发访问时如何保持正确性？
5. **优化：** 用哪些时间、空间、吞吐或可观测性指标验证优化有效？

### 缺失知识点与工程注意事项

- 生产操作前应确认权限、目标环境、配置备份和可回滚方案；不要只验证命令成功退出。
- 回答时应区分标准/系统保证与具体实现细节；未定义行为和未检查错误码不能作为可靠前提。
- 测试至少覆盖正常路径、边界路径和失败路径，并验证资源是否按预期释放或回收。
